## 宿題

- 取り組んだレベル：基礎
- やったこと：`app/judge.py` に回答中の回数を調べるルールベース判定を追加した。第1〜13回以外の「第N回」があれば、LLM の根拠判定が pass や unsure でも、根拠を fail に上書きする。第13回は対象内、第14回と第0回は対象外になること、および LLM の pass を第14回で上書きすることを `tests/test_judge.py` で確認した。
- 結果：変更前（rubric 更新後）の一致率は、根拠 7/10、範囲 10/10、ヒント 9/10、分かりやすさ 10/10、回の表示 3/10。総合 7/10、要確認 0件だった。`uv run python -m app.judge` 再実行後は、根拠 8/10、範囲 10/10、ヒント 9/10、分かりやすさ 9/10、回の表示 3/10。総合 7/10、coverage 100%、要確認 0件だった。結果は `lectures/04/judge_result.json` に保存された。
- 気づき・疑問：第14回の根拠判定はコードで必ず fail になるようになったが、変更前の採点でもLLMは#10を fail としていたため、このルール追加自体は今回の一致率を変えていない。根拠が7/10から8/10に増えたのは、再実行で#08のLLM判定が fail から pass に変わり、自分の pass ラベルと一致したためだった。一方、同じ#08の分かりやすさは pass から fail に変わり、一致率が下がった。再採点の数値変化をコード変更の効果と混同せず、ルールが意図したケースを確実に処理するかと、人のラベルとの一致率を分けて評価する必要がある。
